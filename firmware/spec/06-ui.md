# 06 - User interface: LCD, keys, screens, menus, commissioning

Decided behaviour: `0043` section 6 and 8 (names 6 chars; one setup PIN; protection settings only with the
contact open + ACK). The UI is **outside the trip path**: a dead, slow or unplugged LCD, or a stuck key, never
changes protection timing or decisions (`0042`). Normative for `ui`, `ui_screens`, drivers `lcd` and `keys`.

## 1. LCD driver (`lcd`)

* HD44780-compatible 20x4 (2004A), 4-bit mode, write-only (R/W tied low), pins per `02`. DDRAM line starts:
  line 1 0x00, line 2 0x40, line 3 0x14, line 4 0x54.
* **Non-blocking, frame-buffer pattern:** `ui` writes an 80-char RAM frame; `lcd` copies changed characters to
  the display, at most 8 characters per `ui_task` call (~50 us each with fixed delays, no busy-flag reads since
  R/W is grounded). A full redraw therefore spreads over ~10 loops (< 100 ms).
* Init sequence (datasheet 4-bit init with the 4.1 ms / 100 us waits) runs as a state machine, never as a blocking
  delay. **Re-init every 10 s** and after any `ui` error, so a display that was unplugged, glitched by noise on the
  30-40 cm cable or powered late recovers on its own.
* No read-back exists, so a dead LCD is undetectable by firmware - acceptable: protection does not depend on it.

## 2. Keys (`keys`)

| Item | Rule |
|---|---|
| Sampling | in the 1 ms tick ISR, 8-sample shift register per key (debounce 8 ms) |
| Keys | UP, DOWN, SET, ACK on all boards; ESC pin on 8/40-ch if `board_cfg` has it |
| ESC chord | UP and DOWN both pressed within 150 ms of each other = ESC. When the chord forms, the single UP/DOWN press that started it is cancelled (not delivered). Delivered on release of both. Works on every board (the 24-ch has no ESC pin, `0041` D3). |
| Long press | SET held >= 3 s = `SET_LONG` (open setup) |
| Auto-repeat | UP/DOWN held in an edit field: first repeat after 600 ms, then every 150 ms, after 3 s every 50 ms |
| Release-before-press | after boot, after entering `TRIPPED`, and after any power-up gesture, a key is ignored until it has been seen released; this is how a key held at power-up never becomes an ACK (`04` section 5) |
| Stuck key | a key pressed > 30 s continuously is ignored until released; event not logged (not a protection fault) |
| Power-up gestures | sampled 300 ms after reset: SET held -> service mode (`08`); ACK+SET held -> PIN recovery (5.3) |

## 3. Screens

Status line (line 1) by priority, highest first; the first matching one is shown on every screen except menus:

| Priority | Condition | Line 1 (20 chars) |
|---|---|---|
| 1 | `SERVICE` | `SERVICE MODE    ` + 4-char step |
| 2 | `CONFIG_LOCK` (G01) | `LOCKED: SETUP` |
| 3 | `CONFIG_LOCK` (G10) | `LOCKED: CALIBRATE` |
| 4 | `TRIPPED` | `TRIP ` + first-out (channel: `03 CYL3B`; fault: `B06 BANK A REF`) |
| 5 | `START_LATCHED` | `START: ACK REQUIRED` |
| 6 | `RUN` with active alarms | `ALARM ` + count + `  ` + newest cause short text |
| 7 | `RUN`, degraded CJ (B12 after qualification) | `RUN  DEGRADED CJ` |
| 8 | `RUN` | `RUN OK` + right-aligned `#nnnnn` scan counter last 5 digits (shows the board is alive) |

### 3.1 Home (default; return after 60 s without a key)

Lines 2-4: six channels per page, two per line, 10 chars each: `nn vvvvtM` where `nn` channel, `vvvv` value in
whole C (right-aligned, `----` if not valid, `OPEN` if C01), `t` type letter (`K`, `J`, `P`; space if OFF) and `M`
marker:

| Marker | Meaning |
|---|---|
| ` ` | normal |
| `!` | alarm (active or latched) |
| `#` | trip cause (active or latched) |
| `?` | fault (C01-C03) |
| `-` | channel OFF (value field shows `off `) |
| `a` | ALARM ONLY mode, normal |

Example, 24-ch page 1 of 4:

```
RUN OK        #01234
01  512K  02  498K!
03  505K  04  510K
05  off -  06  493Ka
```

Pages: 8-ch 2, 24-ch 4, 40-ch 8 (channels 41-43 PT100 on page 8 with `P`). UP/DOWN change page. Pages with an
active trip/alarm come first? **No** - order is fixed by channel number so technicians learn positions; the status
line points to the cause.

### 3.2 Channel detail (SET on Home -> choose channel with UP/DOWN -> SET)

```
03 CYL3B  K  TRIP
 512C  CJ  31.2C
AL 480  TR 520  B 5
MIN 498 MAX 516
```

Line 2 shows `OPEN`/`RANGE`/`CM FAIL` instead of the value on a fault. MIN/MAX since the last ACK (RAM only).
ESC back.

### 3.3 Events (from Home: DOWN past the last page)

```
EVENTS  1/32
TRIP 03 CYL3B 523C
 >520  PC 18 T 4:12:09
ESC=back UP/DN=scroll
```

Newest first. `PC` power cycle, `T` uptime h:mm:ss (or `nd hh` above 99 h).

### 3.4 Messages

ACK refusal (`04` section 5) and save results are shown on line 4 for 3 s: `R4 CH 03 HOT/FAULT`, `SAVED OK`,
`SAVE FAILED G02`.

**A new trip always takes over the screen** (Home with the trip status) - also from inside a menu; an uncommitted
edit is discarded.

## 4. Setup menu

Opened by `SET_LONG` from Home, then the PIN (5.1). Idle 5 min -> exit, uncommitted edits discarded.

```
SETUP
 1 CHANNELS        -> pick channel -> Type / Mode / Name / Alarm SP / Trip SP / Band / Probe limit
 2 COMMS           -> Address 1..247 / Baud 9600|19200
 3 SERVICE         -> CAL REF / LEARN BURNOUT / (others only via power-up service mode, 08)
 4 PIN             -> new PIN twice
 5 EXIT
```

| Field | Range / step | Note |
|---|---|---|
| Type | OFF, K, J (PT100 fixed on 40-ch 41-43) | protection field |
| Mode | TRIP, ALARM ONLY | protection field |
| Name | 6 chars, A-Z 0-9 space - / | UP/DOWN letter, SET next position |
| Alarm SP | 0 .. trip-1 C, step 1 C | protection field |
| Trip SP | alarm+1 .. probe limit, step 1 C | protection field |
| Band | 2..50 C | protection field |
| Probe limit | 100 .. type max C, step 10 C | protection field |

### 4.1 Edit -> confirm -> save

Edits change a working copy only. ESC from the channel list asks to commit when anything changed:

```
SAVE CHANGES?
CH03 TRIP 520 -> 510
CONTACT WILL OPEN
SET=save  ESC=discard
```

If more than one field changed, UP/DOWN scrolls the `old -> new` lines. For a names-only change line 3 reads
`NO EFFECT ON RUN`. SET -> commit (`05` section 5): `SAVING...` then `SAVED OK - PRESS ACK` (protection change) or
`SAVED OK`. Validator errors are shown before saving, e.g. `ALARM MUST BE < TRIP`.

## 5. PIN

### 5.1 Entry

Four digits, UP/DOWN change the digit, SET next. Three wrong entries -> locked out for 60 s. The PIN only guards
the setup menu; viewing and ACK need no PIN.

### 5.2 Default

`0000` on a blank board; commissioning forces a change (the PIN step is part of 6). Default printed in the
installation drawing (I-085).

### 5.3 Recovery

Hold ACK+SET at power-up (2): screen `PIN RESET? SET=YES`; SET -> PIN back to `0000`, settings kept, event
`PIN_RESET`, normal start (`START_LATCHED`, so RUN stays open until ACK).

## 6. Commissioning a blank board (what the technician does)

1. Power up: `LOCKED: SETUP`. All channels show `----`.
2. `SET_LONG`, PIN `0000`, set a new PIN.
3. CHANNELS: for each input: Type (K/J or OFF), Mode, Name, Probe limit, Alarm SP, Trip SP, Band. Unused inputs
   OFF. Save.
4. If calibration is missing (`LOCKED: CALIBRATE`): power up in service mode (`08`), run `CAL REF`, connect every
   probe, run `LEARN BURNOUT`, reset.
5. Check every channel reading against a reference (heat one probe, see the right channel rise; polarity, `0038`).
6. ACK -> `RUN OK`. Test one trip (raise a probe above a temporary low trip SP, or lower the SP), restore, ACK.
7. Write the channel map and setpoints on the installation sheet (I-085).
