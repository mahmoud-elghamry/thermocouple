# Family firmware specification - 05 user interface (DRAFT, research input)

Status: draft written for review; `0043` rev 2 wins on any disagreement, `00-overview.md` conventions apply.
Facts marked **[V]** are verified against a source named in the line; **[D]** are design choices made in this draft
and open to change; fault codes `Gnn/Bnn/Cnn` and their 20-character texts come from `03-protection.md` and are not
invented here.

## 0. Notation used in the mock-ups

Every screen is exactly 20 columns by 4 rows. A mock-up row is written between `|` bars; the bars are not displayed.

```
|12345678901234567890|
```

* Characters: HD44780 ROM code range 0x20..0x7D only, except 0x5C (shows as a yen sign in ROM A00). Text going to
  the LCD is sanitised: any other byte becomes `?`. No degree sign (ROM variants differ): temperatures end in `C`.
  No custom characters, no printf, no floating point: fixed-width integer formatting only. All text lives in flash.
* `[V]` the module is a 2004A with an HD44780-compatible controller (SPLC780D1 in the TC2004A-01 datasheet in the
  scratchpad copy). R/W is wired to GND on the J502 header (`hardware/24ch/gen/c_mcu.py`, J502 pin 5 = GND), so the
  controller is write-only: the busy flag cannot be read and all waiting is by time.
* Temperatures on the home grid are whole degrees C (nearest, half away from zero); detail screens show 0.1 C.
* Setpoints, band and probe limit are whole degrees C (0043 section 2.1).
* "Example text" in a mock-up (fault and cause lines) is placeholder; the real strings are `TEXT20(code)` from 03.

## 1. What the UI may read and do

The UI is the only module that talks to the keys and the LCD. It never decides protection, never writes RUN or
ALARM, and a missing or failed LCD, a stuck key or a dead UI task never changes protection timing or outcome.

### 1.1 Read-only snapshot (copied once per completed board scan, so one screen is internally consistent)

| Field | Meaning |
|---|---|
| `scan_no`, `uptime_s`, `power_cycles` | stamps (00 conventions) |
| per channel: `temp_dC`, `valid`, `fault_code` (Cnn or none), `state` (OFF, UNSET, NORMAL, ALARM, TRIP, FAULT, WAIT), `min_dC`, `max_dC` since ACK, `cj_dC`, `emf_nV` (RTD channels: resistance in 0.01 ohm) | channel_eval |
| per channel setting: type, mode, name, alarm SP, trip SP, band, probe limit | settings |
| global: latch reason (NONE, START, TRIP, SETUP, CONFIG_LOCK), RUN actual (read-back), alarm relay actual, `degraded_cj`, active fault list (codes), first-out record (channel or fault, cause code, value, threshold, `uptime_s`, `power_cycles`) | protection |
| event ring (32 entries) | events |
| `ack_possible` and the reason text if not | protection (03 defines the reasons; shown on the LCD, section 5.6) |

### 1.2 Commands the UI may issue (everything else is forbidden)

`protection_request_ack()` (only on a fresh ACK press, section 3.4), `protection_setup_inhibit(true)` (opens RUN, section
7.4), `settings_save_*()` through the settings module (A/B write, read-back, switch; returns OK or an error code),
`events_log(type, ...)` for setting changes, PIN reset and key-stuck, and `settings_set_comms()` (live).
The UI never clears a latch, never closes RUN, never edits a setpoint except through `settings_save_*()` after the flow
of section 7.5.

## 2. LCD driver contract (`ui` HAL part, replaces the 16x2 `hal/lcd.c`)

### 2.1 Wiring and electrical facts

* `[V]` 24-ch (`hardware/24ch/gen/c_mcu.py`): PA0 = LCD_RS, PA1 = LCD_E, PA4..PA7 = LCD_D4..D7 (4-bit bus on J502 pins
  4, 6, 11..14). **PA2 = REFOK and PA3 = REFTEST are on the same port**: LCD writes are masked read-modify-write on
  mask `0xF3` only, executed from the main loop only; no interrupt service routine may write PORTA. Contrast is the
  10k pot RV501 on the board; there is no contrast or backlight control in software.
* `[V]` The LCD is on the door behind a 16-wire cable of 30-40 cm (0042): the driver uses conservative timing, not the
  datasheet minimum.

### 2.2 Timing rules (E pulse, bus, instruction time)

| Item | Value | Basis |
|---|---|---|
| Data stable before E rises | >= 1 us | HD44780 setup 80 ns minimum; x12 margin for the cable [D] |
| E high | >= 1 us (never longer than 20 us) | HD44780 pulse width 230 ns minimum [D] |
| Data held after E falls | >= 1 us | hold 10 ns minimum [D] |
| Time between instructions or data bytes | >= 60 us measured from the second E falling edge | typical instruction 37 us, +margin [D] |
| Clear display (0x01) | wait >= 2 ms; used only inside init | typical 1.52 ms |
| Power-on to first init nibble | >= 50 ms after the LCD gets 5 V (and >= 50 ms after reset) | datasheet needs >40 ms at 4.5 V |
| Init nibble waits | after first 0x3: >= 5 ms; after second 0x3: >= 200 us; after third 0x3 and after 0x2: >= 200 us | HD44780 "initialisation by instruction" |

The datasheet text in the scratchpad (`tc2004a.txt`) contains only the prose; its timing and command tables are
images. The values above are the HD44780 standard figures and the repo's existing 8-ch driver constants (5 us E, 100 us
gap, 50 ms power-on); confirm against the purchased module's own sheet when it arrives (OPEN-1).

### 2.3 Addressing for 20x4

DDRAM address of column 0 of each row: row 1 = `0x00`, row 2 = `0x40`, row 3 = `0x14`, row 4 = `0x54`
(`[V]` the 20x4 map of HD44780 modules: row 3 continues row 1's address space, row 4 continues row 2's). Command to set
the cursor = `0x80 | address`. The controller auto-increments the address, but at the end of a row it does **not** wrap to
the next screen row, so the driver sets the address at the start of every run of writes and never relies on wrap.

### 2.4 Init sequence (time-sliced state machine; never blocks)

1. Wait 50 ms (from the system tick, not a delay loop).
2. Nibble `0x3` ; wait 5 ms ; nibble `0x3` ; wait 200 us ; nibble `0x3` ; wait 200 us ; nibble `0x2` (4-bit mode) ; wait 200 us.
3. Command `0x28` (4-bit, 2-line mode which is the 4-row 20-column addressing, 5x8 font).
4. `0x08` display off ; `0x01` clear (wait 2 ms) ; `0x06` entry mode increment, no shift ; `0x0C` display on, cursor
   off, blink off.
5. Mark every cell dirty (section 2.5).

### 2.5 Refresh strategy (the protection-timing guarantee)

* The UI renders into an 80-byte frame buffer. A second 80-byte shadow buffer holds what the LCD is believed to show.
  A cell is *dirty* when the two differ.
* `lcd_service()` is called once per main-loop pass and does **at most one** of: send one nibble pair (one character
  or one command), or nothing. It first checks that >= 60 us have passed since the previous send (16-bit free-running
  microsecond counter from `timer`; if the build has only the 1 ms tick, one byte per tick is acceptable: a full
  refresh then takes about 100 ms). It never loops waiting for the LCD.
* Worst-case CPU per `lcd_service()` call: 15 us (two nibbles, three 1 us holds each) [D]. Worst-case `ui_render()` for
  a screen: 500 us, and it is not called more often than every 250 ms or when the screen changes (key, new snapshot). The
  sum can never delay the protection step by more than the longest single call.
* Writing order: scan dirty cells round-robin from the last position; if the next dirty cell is not at last address + 1
  within the same row, first send a set-address command.
* **Periodic healing:** every 5 s all cells are marked dirty (rewritten even if unchanged); every 30 s a soft re-init is
  queued before that rewrite (steps 3, 4 without clear and without display-off: `0x28`, `0x0C`, `0x06`). A noise glitch
  on the long cable therefore shows for at most 5 s (a lost mode setting for at most 30 s).
* A missing, unplugged or dead LCD cannot be detected (write-only) and does not need to be: the driver only toggles
  output pins. Keys, ACK and all protection continue unchanged. Service mode (07) lists the LCD as "check by eye".
* No `_delay_ms`/`_delay_us` longer than 2 us in any UI code path. The 8-ch driver's 50 ms blocking init must not be reused.

## 3. Keys

### 3.1 Hardware per board

| Board | Keys and pins | ESC |
|---|---|---|
| 24-ch `[V]` (c_mcu.py, 0041 D3) | UP = PD2, DOWN = PD3, SET = PD4, ACK = PD6 (all active low, internal pull-ups) | **no pin**: ESC pulls UP and DOWN low together through two diodes; firmware reads UP+DOWN as ESC. Five panel buttons, same as the family. |
| 8-ch and 40-ch `[V]` (`main:hardware/family/gen/boards.py`, ESC pin PD5) | UP = PD2, DOWN = PD3, SET = PD4, ESC = PD5, ACK = PD6 | pin PD5, and the UP+DOWN chord also works (0043 section 6) |

The `board_cfg` flag `HAS_ESC_PIN` (8-ch, 40-ch) selects whether PD5 is read as a key; on the 24-ch PD5 is SIO_WR_N
(output) and must never be read as a key.

### 3.2 Sampling and debounce

* Sample all keys every 5 ms (from the 1 ms tick; if the UI pass is late, take one sample per pass but never more than
  one per 5 ms).
* A key changes its stable state only after **6 consecutive equal samples (30 ms)**, in both directions.
* Key events go into a 4-entry queue; when it is full, new events are dropped (a lost key press is never dangerous;
  a duplicated one could be).

### 3.3 Events produced

| Event | When it fires |
|---|---|
| `UP`, `DOWN` | on press, after the chord window of 3.5 (first event after >= 60 ms), unless it was a chord |
| `ESC` | UP+DOWN chord, or the ESC pin on 8/40-ch |
| `SET_SHORT` | on **release**, if the hold was < 3.0 s and `SET_LONG` has not fired |
| `SET_LONG` | once, when SET has been held 3.0 s (+-10 ms); the release afterwards fires nothing |
| `ACK` | on press, only when armed (3.4) and no other key is down |
| auto-repeat `UP`/`DOWN` | only on numeric edit screens (3.6) |

Any other combination (for example ACK+UP) produces no event for the second key; the first key's event, if it already
fired, stands. ACK pressed while any other key is down fires nothing and is consumed until released.

### 3.4 Release-before-press (fresh press) rule

Each key has an `armed` flag. It is cleared: at boot, when a trip or latch begins, and after any gesture (chord, service
or recovery entry, setup entry). It is set when the key has been stable-released for >= 100 ms. A key that is not armed
produces no events when pressed. This is the rule 0043 section 3.5 requires for ACK ("must be seen released after boot,
after the trip and after any service/recovery gesture"); it is applied to every key for simplicity. A key held at power-up
(not a boot gesture) therefore does nothing until released.

### 3.5 UP+DOWN chord

* The first of UP or DOWN to go low starts a 60 ms chord window; the single-key event is held back.
* If the other key goes low (raw sample, not debounced) within the window, the result is `ESC` and both keys become
  *consumed*: no UP, DOWN or ESC repeat comes from them until **both** are stable-released.
* If the window ends with only one key down, that key's event fires. If the second key then goes low later than the
  window, it is ignored (consumed until both are released), so a slow second finger cannot turn a page.
* Chord has precedence over single keys. The 60 ms delay applies only to the first event of each press.
* On the 24-ch the ESC button (two diodes) pulls both low at once, so it is always seen as a chord.

### 3.6 Auto-repeat (numeric edit screens only)

Hold UP or DOWN: first step at once, then after 500 ms one step per 100 ms; after 2 s of holding, 10 units per 100 ms.
At either end of the range the value stops (no wrap); enumerations and single digits never repeat and wrap around.
Menu cursors and pages never repeat.

### 3.7 Stuck-key handling

A key stable-pressed for more than 30 s (SET and ACK included; SET is exempt only during the 2 s hold in service
mode) is declared stuck: it produces no more events and is ignored until stable-released; a `KEY_STUCK` event is logged
once per key per power cycle. A stuck ACK means the technician cannot ACK; the home status line is unchanged (the
protection state is the truth). Nothing in the trip path depends on a key.

## 4. Screen structure

### 4.1 Screens and navigation

```
BOOT SPLASH (1.5 s) --> HOME grid <--ESC-- VIEW menu --> CHANNELS list --> CHANNEL detail (2 pages)
                         |   |  SET short     |           EVENTS (one per screen)
                         |   |                |           FIRST-OUT / LAST TRIP
                         |   |                |           FAULTS (one per screen)
                         |   |                '---------- ABOUT
                         |   '-- UP/DOWN: previous/next page (wraps)
                         '------ SET held 3 s: PIN --> SETUP menu tree (section 7)
```

### 4.2 Global rules

* **Return to home:** any screen outside setup returns to HOME after 60 s without a key (list positions reset).
* **Setup idle:** setup closes after 5 min without a key; uncommitted edits are discarded; anything already saved and
  verified stays. See 7.6.
* **A new trip takes over the screen.** When a latch episode gets its first-out (a trip is the first cause since the
  last ACK), the FIRST-OUT screen (6.4) is shown at once from **any** screen, including inside setup. It is an *overlay*:
  ESC or SET returns to the screen below it (HOME if there is none, on the page that holds the first-out channel); the
  state of any open edit is kept. UP/DOWN switch between its two pages. An overlay left alone for 60 s returns to HOME.
  A second trip while a first-out already exists does not take over (it is logged, marked on the grid, and listed in
  EVENTS); the first-out stays at the top until ACK. (Interpretation of 0043 "a new trip always takes over"; see OPEN-3.)
* **Contrast** is a board potentiometer (RV501) - no software setting.
* LCD text for a fault is always `<code>` on one line (for example `C07`, `B02 A`, `G12`) and the 20-character text from
  03 on the line below, never truncated and never invented.

## 5. Home screen

### 5.1 Layout

Row 1 = status line (columns 1-19) and the page digit (column 20). Rows 2-4 = two channels per row, six per page.
Each channel cell is 9 characters, a blank column between the cells:

| Columns of a cell | Content |
|---|---|
| 1-2 | channel number `01`..`43` |
| 3 | blank |
| 4-7 | temperature, whole degrees, right-aligned (` 412`, ` -20`, `1400`); `----` fault or unset, ` OFF`, `....` not measured yet |
| 8 | `C` after a number, else blank |
| 9 | marker |

Right cell starts in column 11. The channel name is **not** on the grid (no room next to number and temperature); it is
on the CHANNELS list and the detail screen.

### 5.2 Markers (column 9 of a cell; first match wins)

| Marker | Meaning | Value shown |
|---|---|---|
| `*` | channel not configured (type unset, or setpoints missing): config lock | `----` |
| `?` | active sensor or channel fault (Cnn) | `----` |
| `#` | channel latched a trip, not yet cleared by ACK | value |
| `!` | alarm: value >= alarm SP | value |
| `-` | channel OFF | ` OFF` |
| `a` | ALARM ONLY mode, normal | value |
| blank | normal TRIP-mode channel | value |

Empty positions on the last page are blank cells.

### 5.3 Status line (columns 1-19), first match wins

| Priority | Text | Condition |
|---|---|---|
| 1 | `LOCKED: SETUP` | config lock: settings blank, invalid, or a channel unconfigured; RUN never granted |
| 2 | `TRIP 03 CYL3B` | latched trip, first-out channel and name (one more word if short: name is the 6-char name; blank name shows nothing) |
| 2 | `TRIP G12` / `TRIP B02 A` | latched trip whose first-out is a global or bank fault (code from 03) |
| 3 | `SETUP INHIBIT: ACK` | RUN held open because of a setup session, ACK needed (7.4) |
| 4 | `START: ACK REQUIRED` | latched at power-up/reset/brown-out/watchdog, no trip |
| 5 | `DEGRADED CJ` | running on one cold-junction sensor (0043 3.4); ALARM is on |
| 6 | `ALARM 2` | running; count of channels in alarm (1..43) |
| 7 | `RUN OK` | RUN contact closed per read-back, no alarm, no warning |
| - | `SERVICE ...` | service mode screens only (07) |

`RUN OK` is shown only when the **read-back** of RUN says closed, never because protection has permitted it.
Text `START: ACK REQUIRED` is 19 characters and uses the whole status field, which is why the page digit is the last
column and the status field is 19 wide.

### 5.4 Paging and page counts

6 channels per page; UP = previous page, DOWN = next page (wraps). Page digit in column 20.

| Board | Channels | Pages | Page contents |
|---|---|---|---|
| 8-ch | 1-8 | 2 | 1: ch 1-6, 2: ch 7-8 |
| 24-ch | 1-24 | 4 | 1: 1-6, 2: 7-12, 3: 13-18, 4: 19-24 |
| 40-ch | 1-40 and PT100 41-43 | 8 | pages 1-6: 1-36, page 7: 37-40, page 8: PT100 41-43 (own page: different sensor) |

### 5.8 Why ACK is refused

If ACK is pressed and `ack_possible` is false, rows 2-4 are replaced for 3 s by the reason (text from 03, wrapped to

After 3 s the home grid returns. A refused ACK is not logged as an event.

### 6.4 FIRST-OUT / LAST TRIP

While a latch with a first-out exists the title is `FIRST-OUT`; afterwards it shows the most recent trip event from the
log as `LAST TRIP` (trip history is kept after ACK, 0043 section 5). Value and threshold at the moment of the trip.
Channel trip, page 1:
```
|FIRST-OUT 03 CYL3B  |
|OVER TRIP SP (EXMPL)|
|VAL 612C  SP 600C   |
|UP 012d 05:33:07    |
```
Global or bank fault as first-out (the code is the title, text from 03 on the next row; no value or threshold):
```
|FIRST-OUT FAULT G12 |
|ADC A ID (EXMPL)    |
|PC 0042             |
|UP 012d 05:33:07    |
```
Page 2 (UP/DOWN) of a channel trip lists the other trips of the same latch episode, one per page (channel, cause code),
then `NO MORE` after the last.

### 6.5 EVENTS (one event per screen; UP = older, DOWN = newer, ESC = back)

32 entries (04 owns the record). The name is the current name of the channel (names can change; the event keeps the
number). Empty log: `NO EVENTS` on row 2.
```
|EVENT 01/32  PC 0042|
|UP 012d 05:33:07    |
|TRIP 03 CYL3B       |
|612C >= 600C        |
```
| Event type | Row 3 | Row 4 |
|---|---|---|
| trip, channel | `TRIP nn NAME` | `value >= trip SP` or fault code and text start |
| alarm | `ALARM nn NAME` | `value >= alarm SP` |
| fault, global/bank/channel | code (`G12`, `B02 A`, `C07`) | text from 03 |
| ACK | `ACK` | blank |
| power-up | `POWER-UP` | reset cause (`POWER`, `WATCHDOG`, `BROWNOUT`, `EXTERNAL`) |
| setting change | `SETTING CHnn` | item and new value, e.g. `TRIP SP 620C` |
| PIN reset by recovery gesture | `PIN RESET` | blank |
| key stuck | `KEY STUCK` | key name |

Uptime format `UP ddd d hh:mm:ss` counts since the last power-up; `PC` is the power-cycle counter, so events from different
power-ups are never confused (there is no clock).

### 6.6 FAULTS (active faults, one per screen)

```
|FAULTS 1/2          |
|G12                 |
|ADC A ID (EXMPL)    |
|UP/DOWN=NEXT        |
```
Empty: `NO ACTIVE FAULTS`.

```

|SCANS 123456  0.70 S|

```
(Board type 8CH/24CH/40CH, firmware version, build number and image CRC, scan count and last scan time, uptime and power

## 7. Setup

### 7.1 Entry and PIN

SET held 3 s on HOME or any view screen (not on edit screens) -> PIN screen. One PIN, four digits, default `0000`
(blank board and after recovery). Digit entry: UP/DOWN change the current digit (0-9, wraps), SET short = accept the digit
and move on, after the 4th digit SET checks the PIN, ESC = previous digit (cancel on the first).
```
|ENTER SETUP PIN     |
|PIN: *5__           |
|                    |
|UP/DN SET=NEXT ESC  |
```
Wrong PIN: `WRONG PIN` / `TRIES LEFT 2`. Three wrong entries lock PIN entry for 60 s (`PIN LOCKED 60S` counting down; counter
in RAM only; a power cycle resets it; physical access is already required, recovery is 7.8). No PIN entry timeout beyond
the 60 s return to HOME.

### 7.2 Menu tree

```
SETUP
+- CHANNELS      -> channel list (N entries, like 6.2 but with type/mode) -> CHANNEL menu
      +- TYPE        OFF / K / J (RTD / OFF on 41-43)                   protection
      +- MODE        TRIP / ALARM ONLY                                   protection
      +- ALARM SP    whole C                                             protection
      +- TRIP SP     whole C                                             protection
      +- BAND        2..50 C                                             protection
      +- LIMIT       probe limit, whole C                                protection
      +- NAME        6 characters                                        live
+- COMMS         -> ADDRESS 1..247 | BAUD 9600/19200 | PARITY NONE/EVEN/ODD   live
+- SERVICE       -> INFO (read-only: settings A/B, calibration, power cycles) | HOW TO ENTER SERVICE MODE
+- PIN           -> new PIN, repeat PIN                                   live
+- EXIT
```
Items marked *protection* require RUN inhibit and a new ACK (7.4); *live* items apply immediately on save. When the
channel type is OFF or unset the CHANNEL menu offers only TYPE and NAME. An optional convenience is **COPY SETTINGS**
(Channels menu, last item): copy type, mode, SPs, band, limit (not name) from channel X to channels Y..Z, with the same
confirm/save flow per channel. It exists to save 100+ key edits on a 24 or 40-channel board; it is proposed, not
decided (OPEN-5).

### 7.3 Item ranges and steps

| Item | Values | Step | Blank board | Rule |
|---|---|---|---|---|
| TYPE | OFF, K, J (RTD, OFF on 41-43) | cycle | unset (`---`) | change clears alarm SP, trip SP; limit = type max; samples discarded; ACK needed |
| MODE | TRIP, ALARM ONLY | cycle | TRIP | ALARM ONLY confirm shows `NO TRIP ON THIS CH` |
| ALARM SP | 0 .. (trip SP - 1), or 0 .. (limit - 1) when trip is unset | 1 C | unset (`----`) | |
| TRIP SP | (alarm SP + 1, or 1) .. limit | 1 C | unset | |
| BAND | 2 .. 50 | 1 C | 5 | |
| LIMIT | max(50, trip SP) .. type max (K, J, RTD from 02; placeholder K 1370, J 1200, RTD 850 - OPEN-2) | 10 C | type max | bounds both SPs |
| NAME | 6 characters from: space, A-Z, 0-9, `-`, `.`, `/` | cycle | blank | live, no inhibit |
| ADDRESS | 1 .. 247 | 1 | 1 | |
| BAUD | 9600, 19200 | cycle | 9600 | |
| PARITY | NONE (8N2), EVEN (8E1), ODD (8O1) | cycle | NONE | see 06 |
| PIN | 4 digits | - | 0000 | |

An unset setpoint is never invented: its editor opens showing `----`; the first UP loads the lowest legal value, the first
DOWN the highest; SET on `----` is ignored and row 4 shows `ENTER A VALUE`.

### 7.4 RUN inhibit and ACK for protection settings (0043 section 3.7)

Before the first protection edit of a session, if RUN is currently granted, this screen appears; SET opens the RUN
contact (the latch reason becomes SETUP) and starts editing; ESC cancels and nothing changes:
```
|PROTECTION SETTING  |
|RUN CONTACT OPENS   |
|ENGINE MAY STOP     |
|SET=OK  ESC=CANCEL  |
```
If RUN is already open (blank board, config lock, latched trip or start) no warning is shown, but the SETUP reason is
still recorded. The inhibit stays until ACK after the technician has left setup and the normal ACK conditions of
0043 3.5 are met; the home status is `SETUP INHIBIT: ACK` meanwhile. Names, comms and PIN edits do not inhibit.

### 7.5 Edit -> confirm -> save -> read-back

Edit works on a RAM copy; nothing is written until the confirm screen.
```
|CH 03 CYL3B TRIP SP |
|OLD 600C  1..1000C  |
|NEW 620C            |
|UP/DN SET=OK ESC=NO |
```
SET -> confirm (the third row is a warning where it applies, otherwise blank):
```
|CONFIRM CH03 TRIP SP|
|OLD 600C            |
|NEW 620C            |
|SET=SAVE  ESC=BACK  |
```
Type change (warns that setpoints are cleared) and OFF:
```
|CONFIRM CH03 TYPE   |
|OLD K     NEW J     |
|SETPOINTS CLEARED   |
|SET=SAVE  ESC=BACK  |
```
```
|CONFIRM CH03 TYPE   |
|OLD K     NEW OFF   |
|CH NOT MONITORED    |
|SET=SAVE  ESC=BACK  |
```
SET -> `SAVING...` (row 2) while the settings module writes the older A/B copy, reads it back and switches. Then:
```
|SAVED + VERIFIED    |
|CH03 TRIP SP 620C   |
|RUN CONTACT OPEN    |
|ACK AFTER EXIT      |
```
For live items rows 3-4 are blank. Saving a protection item that leaves an alarm/trip unset or the channel
unconfigured leaves config lock on (`LOCKED: SETUP`). On failure the old value stays active and a fault latches until a
later save succeeds (0043 section 5; the fault code and text are from 03/04):
```
|SAVE FAILED  G19    |
|(TEXT FROM 03/04)   |
|OLD VALUE KEPT      |
|SET=RETRY ESC=BACK  |
```
Name edit: UP/DOWN cycle the character, SET moves to the next of the six, after the sixth SET goes to the confirm screen
(`OLD CYL3A` / `NEW CYL3B`), ESC = previous character (cancel on the first). PIN change: new PIN, repeat PIN
(`PINS DIFFER` on mismatch), then the same confirm/save.

### 7.6 Timeouts and aborts

* Setup closes after 5 minutes without a key: `SETUP TIMEOUT` for 2 s, then HOME. Open edits are discarded; saved items
  stay saved; the inhibit (if opened) stays until ACK.
* A trip overlay (4.2) never discards an edit. The 5 minute clock continues underneath.
* ESC from an edit screen or confirm screen discards that edit. Leaving the menu with EXIT or ESC from the top-level menu
  ends the session; the PIN is needed again for the next one.

### 7.7 SERVICE submenu

INFO: read-only screens (settings A/B sequence and CRC state, calibration present or not per bank, power cycles, uptime).
HOW TO ENTER SERVICE MODE:
```
|SERVICE MODE        |
|POWER OFF. HOLD SET |
|WHILE POWERING ON.  |
|RUN STAYS OPEN      |
```
Nothing in setup starts service mode; the entry is the power-up gesture of 8.

### 7.8 Recovery (forgotten PIN)

Hold **ACK+SET** while powering up (the splash screen of section 8 shows it): after the 1.5 s window the PIN becomes the
default, settings are kept, RUN is inhibited (it is anyway latched at power-up), an event `PIN RESET` is logged and the
screen shows `PIN RESET TO DEFAULT` for 3 s. All keys are re-armed (3.4) after the gesture.

## 8. Boot, splash and gestures

```
|THERMO 24CH  V1.0.0 |
|BUILD 0042 CRC 3FA1 |
|SET: SERVICE MODE   |
|ACK+SET: PIN RESET  |
```
* The splash is shown 1.5 s after reset. It does not delay the protection start: protection runs its own start-up
  (latched, START) in parallel; ACK is ignored during these 1.5 s (not armed).
* Sampling: from 0.5 s to 1.5 s after reset; all samples must show the same key pattern. `SET` only -> service mode (07);
  `ACK` and `SET` -> PIN recovery; any other pattern -> no gesture, held keys are ignored until released (3.4).
* **Order of precedence at boot:** a gesture overrides the normal screen; service mode ends the normal start for good
  until the next reset (07).

## 9. Commissioning a blank board (step by step)

Blank EEPROM (no settings record, or invalid): config lock, RUN never granted.

1. **Power up.** Splash 1.5 s, then:
```
|LOCKED: SETUP      1|
|01 ---- * 02 ---- * |
|03 ---- * 04 ---- * |
|05 ---- * 06 ---- * |
```
2. **Enter setup.** Hold SET 3 s. PIN `0000` (UP/DOWN none needed: SET four times).
3. **COMMS** (optional): ADDRESS, BAUD, PARITY, each with confirm (live).
4. **PIN** (recommended): new PIN twice.
5. **CHANNELS**, for each fitted channel, in this order: TYPE (clears nothing on a blank board), MODE (default TRIP is
   kept unless ALARM ONLY is wanted), LIMIT (default is the type maximum), ALARM SP, TRIP SP, BAND (default 5), NAME. No
   RUN warning appears because RUN is already open; every protection edit is still confirm -> save -> read-back.
   Channels not used: TYPE OFF (explicit), which clears the `*`. COPY SETTINGS (if kept) fills channel groups.
6. **Check** the Channels list: no channel shows `---` in the type column.
7. **EXIT.** Home shows `SETUP INHIBIT: ACK` (or `LOCKED: SETUP` while any channel is still unset).
8. **ACK** (fresh press). If a channel is not yet below trip SP minus the band or has a sensor fault, row 2-4 show why
   (5.8); fix it and press ACK again. Home shows `RUN OK` when the RUN read-back says closed.

## 10. Implementation limits and tests the draft expects (to be listed in 08)

* UI RAM budget: frame + shadow 160 B, key queue 8 B, edit copy < 64 B, snapshot copy of per-channel fields <= 43 x 16 B.
* `ui_render()` <= 500 us, `lcd_service()` <= 15 us per call; host test counts operations; the on-target budget is
  measured with a scope on a spare pin.
* Host tests: debounce edges; chord inside and outside the 60 ms window; held keys at boot; ACK suppressed with another
  key down; SET short vs long; stuck key 30 s; auto-repeat ranges; every status line priority; marker priority; paging for
  8/24/40; setup flows: PIN lockout, edit/confirm/save/failure, timeout discarding edits, trip overlay inside an edit.
* Fault injection: LCD pins held low or high (no effect on `scan_no` progress or RUN deadline); UI task stalled (protection
  still trips); keys shorted (all stuck).
